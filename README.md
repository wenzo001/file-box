# 文件盒子（File Box）

轻量、内网零配置的团队文件库：按项目组 / 个人 / 任务建文件夹，上传、下载、重命名、移动、删除都在目录里完成；旧的时间戳上传自动归入「未分档」。文件在浏览器内端到端加密，服务器只存密文；目录名与目录结构对服务器可见。每次上传默认 1 小时后自动删除（可选 1h / 4h / 8h / 2d / 3d / 5d / 10d / 90d），文件夹只手动删除。PC 与手机浏览器均可使用。

## 功能特性

- 上传：在目录里点「上传」或直接把文件拖进来，立即进入任务中心；可暂停 / 继续 / 取消，刷新后还能重选同一批文件续传。单文件无大小限制，分块顺序只由文件路径 + 大小决定
- 分块续传：上传按块进行（每块约 4MiB，按加密块边界切，最后一块是余数），进度是一块一块点亮的长条 —— 文件越大格子越多，格子多了自动换行并整体缩小格子，**整条始终一眼看全，不在里面做滚动**。下面同步写着「已传 66/127 块 · 52% ｜ 约 264.0 MB / 504.1 MB，一格 ≈ 4.0 MB」，说明每一格代表多大、已经发出去多少
- 分块可复现：分块边界只由「文件相对路径 + 大小」决定，**与设备、端口、浏览器有没有硬件加密无关**。下次哪怕换了选择顺序、从 `http://内网IP` 换到 `https://` 重选同一批文件，切出来的块和上次完全一样，已传的那几块直接接着用（不会因为换了引擎就白传）
- 续传时效与边界：未完成的批次在 `.uploading/` 保留 **2 天**（`UPLOAD_TTL_HOURS` 可调，默认 `48`），超时自动回收、下次上传从头再来。**服务重启不打断续传**（只丢掉写了一半的块，已验完的块留着）。同时最多保留 20 个未完成批次，超了挤掉最久没动的；单批最多 200 个文件、单块最大 32MB；同时写入超过 8 块时服务端回 429，客户端会自动退避重传那一块（进度不丢）。合并中途失败时整批作废重来，绝不留「拼了一半的文件」
- 稳定与完整：每块都带自身 CRC32，服务端校验通过才落盘；网络抖动 / 被中途掐断 / 路上被改坏都会**自动重传该块（最多 3 次）**，三次都没过才停下并把进度、清单原样留着，点一下就能接着传。停下之后不会再有"后台还在偷偷传下一块"的事：界面上写着传到哪，就是真的传到哪。下载侧由每块的 GCM 校验把关：密文被改坏或长度对不上会明确报错，绝不会给你一个看起来正常、其实是坏的/半截的文件
- 手机端不卡页面：手机走 HTTP 访问时没有硬件加密，加密、拼块、算校验全部放在工作线程里做，主线程只发请求。实测手机 CPU 降频 6 倍、80MB 一个文件：上传全程最长一次卡顿 0.1 秒（改之前是 2.5 秒，进度条会停在 60% 不动），JS 内存峰值 11MB 且不随文件大小增长
- 隐私保护：文件在浏览器内自动加密后才上传，服务器磁盘只保存密文，需通过本页面下载查看；密文长度还会向上补到 64KiB 的整数倍，服务端和中间设备连"这个文件精确多大"都看不出（真实大小只记在加密的清单里）
- 存储与保留期：总量上限默认 10GB；每次上传默认 1 小时后自动删除，可选 1h / 4h / 8h / 2d / 3d / 5d / 10d / 90d；文件夹永不自动删除，只能手动删；用量条实时显示
- 无全局自动清理：文件和目录保留到手动删除（或本次上传的 TTL），避免旧备份或长期项目资料因为日期老而被静默清掉
- 目录式管理：侧栏 + 面包屑 + 文件表格；按项目组 / 个人 / 任务建文件夹，上传、下载、重命名、移动、删除都在当前目录完成；支持搜索、点列头排序、多选删除
- 旧数据零迁移：没有索引条目的时间戳批次自动归到「未分档」，原分享链接与下载次数不变；可以整批移动到正式目录
- 列表刷新：每 10 秒轮询；新文件 / 目录自动出现；当前目录、搜索与选择状态不被轮询打断
- 任务中心：上传 / 下载 / 目录删除都有进度、暂停、继续、取消；刷新后未完成上传会列出来，重选同一批文件即可续传
- 下载：单文件下载支持 HTTP Range 断点续传，OPFS 暂存 partial；任务中心可暂停 / 继续 / 取消。目录打包下载尚未接入新界面（旧 `/api/archive/:batch` 仍保留给兼容调用）
- 删除：文件 / 文件夹都能删；文件夹删除按「批次 → 最深子目录 → 父目录」逐项执行，任务中心可暂停 / 继续 / 取消；二次确认
- 地址分享：顶栏「链」复制当前目录直达链接（`?f=<id>`），旧 `?folder=<批次>` 链接仍能打开；无痕传输是独立入口
- 自动适配 PC / 移动端；前端 Vue 3 + Vite + Reka UI 无头组件，视觉沿用原有 token
- 端口可自定义，HTTP / HTTPS 双端口，基于 pm2 部署
- 无痕传输：顶栏独立入口，选文件出一个一次性传输码（32 字符），对方在另一台设备输入即可收文件，也可以直接发页面上那条接收链接（点开自动进接收页，码跟在 `#` 后面所以不进服务器日志）。**同一个局域网优先点对点直连**：服务端自带一个极简 STUN（udp 3478），两端据此拿到自己的真实内网地址，绕开浏览器 mDNS 候选常常解析不了的那一层；直连没在 8 秒内建起来也**不会掐死它**，先把进度切到中转推起来，直连晚到就自动切回去。不通再走 TURN 或本服务器密文中转；全程端到端 AES-256-GCM，服务器只见密文帧不见文件名。**后台标签页不再被冻结**（会话期间持一把 Web Lock），断了能接着传、卡住了那颗键就是「继续传输」。做完/过期就清理，不写进文件库，链接也随会话失效。**界面会如实说清现在走的是哪条路**：直连 / 服务器中转 / TURN 中继 / 正在建直连 / HTTP 降级，各有一个颜色和一颗标签，旁边写着"快不快、为什么、怎么办"；块进度条按帧推进，**校验（逐块复核 + 总 SHA-256）与写盘也各有百分比**，这两段保存键会提前露出来但按不动、写明"校验中，还不能保存"。**"到底清没清"可以自己核对**：页面底部有「服务器残留核验」，不需要密码，输了码就告你还剩几段、多少字节、最晚几点自动清 —— 这条是给"本地记录已经在隐私模式里丢了"准备的。详见 [`docs/transfer.md`](docs/transfer.md)

## 环境要求

- Node.js ≥ 18
- pm2（全局安装）：`npm install -g pm2`

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 构建前端（Vue + Vite，产物在 dist-web/）
npm run build

# 3. 启动（Express 同时托管 /api 与 dist-web）
npm start
# 或 node server.js
```

启动后浏览器访问：`http://服务器IP:3000`（也支持 `https://服务器IP:3443`，见下文「HTTP 与 HTTPS」）。
`npm start` 前必须先 `npm run build`；没构建时启动日志会提示，根页面会 404。

### 前端开发（Vue + Vite）

```bash
# 终端 1：API 服务
npm run dev:server

# 终端 2：Vite 开发服务器（5173，/api 与静态源代理到 3000）
npm run dev

# 改完前端要出生产页面时
npm run build
```

## 打包（出自包含发布产物）

```bash
npm run pack
# 产物：dist/file-box-1.0.0.tar.gz（大小与文件数见打包输出）
#      dist/file-box/                同内容的目录，可直接跑
```

**这个包是自包含的**：生产依赖已按 `package-lock.json` 的生产闭包一起打进去，
服务器上**不需要再 `npm install`**，解压就能启动。（只有一个是例外：Node.js 运行时本身不在包里，
目标机仍要有 Node ≥ 18 —— 要连 Node 一起带，就得走容器或单文件打包，那是另一套做法。）

包里只有两类东西：

- 应用文件 —— `server.js`、`dist-web/`（Vue 构建产物 + 从 `public/` 复制来的静态源）、`lib/`、`docs/`、`package.json`、
  `package-lock.json`、`ecosystem.config.js`、`README.md`
- `node_modules/` —— 生产依赖闭包，按锁文件精确收集

**刻意不进包**（打包脚本逐条自检，违反就直接失败退出，不会出一个跑不起来的包）：

- `uploads/` —— 你的文件数据都在这里；`.certs/` —— HTTPS 私钥，每台服务器各自生成
- `.env`、`*.log`、`.git/`、`scripts/`、`dist/`
- dev 依赖，以及 npm 的账本文件与按平台生成的 `.bin` 启动器

> ⚠️ **一个前提**：带 `node_modules` 跨机器跑，成立的条件是依赖全是纯 JS。
> 当前生产依赖（express / selfsigned / zod / @seald-io/nedb）及其纯 JS 传递依赖都没有原生二进制、
> install 脚本或 os/cpu 限定，所以从 Windows 打包带到 Linux 可用 —— 打包脚本每次都会重新检查这一点，
> 将来若引入了带 `.node` 二进制的依赖，打包会直接失败并提示改在目标系统上打包。

> 前端现在是 Vue 3 + Vite 构建：源码在 `web/`，构建产物 `dist-web/` 由 Express 直接托管；
> 目标机不需要 Vite，也不需要单独数据库服务。`npm run pack` 会先 `npm run build`。
> **改了 `package.json` 的依赖**，要先 `npm install` 再 `npm run pack`，包里才是新的依赖。

## 生产部署（跑 dist）

```bash
# 1. 本地打包并传到服务器
npm run pack
scp dist/file-box-1.0.0.tar.gz user@server:/tmp/

# 2. 服务器上解压到部署目录（不需要 npm install）
mkdir -p /opt/file-box
tar -xf /tmp/file-box-1.0.0.tar.gz -C /opt/file-box --strip-components=1

# 3. 启动
cd /opt/file-box
pm2 start ecosystem.config.js
pm2 save

# 4. 验证（端口以 ecosystem.config.js 的 env.PORT 为准：pm2 方式默认是 4444，
#    直接 npm start 不带配置才是 3000）
curl -s http://127.0.0.1:4444/api/list | head -c 200
```

> ⚠️ **数据就在应用目录里**：`uploads/` 与 `.certs/` 不在发布包中，但运行时会生成在
> 应用目录下。**升级时不要用「删掉整个目录再解压」的方式**，否则历史文件会被一起删掉。
> 正确做法是解压覆盖（`tar -xf` 只覆盖同名文件，不会删除多余文件）。

### 升级与回滚

```bash
# 升级：先备份数据（uploads + 目录索引 + 下载账本），再解压覆盖，最后重启
cd /opt/file-box && tar -czf /tmp/file-box-data-$(date +%F).tar.gz uploads $(ls -d .stats .library 2>/dev/null)
tar -xf /tmp/file-box-<新版本>.tar.gz -C /opt/file-box --strip-components=1
cd /opt/file-box && pm2 restart file-box   # 依赖已在包里，不用 npm install

# 回滚：用旧版本包再覆盖一次即可（uploads/ 不受影响）
tar -xf /tmp/file-box-<旧版本>.tar.gz -C /opt/file-box --strip-components=1
pm2 restart file-box
```

> 恢复备份时先停服务再导入 `uploads/`、`.stats/`、`.library/`；当前版本没有按天自动清理，旧目录不会因为日期老而在启动时被删除。
> 如果只恢复 `uploads/` 而没有 `.library/`，文件仍在，但目录树与 TTL 会丢失，所有批次会回到「未分档」；`.stats/` 丢失只会让下载次数归零。
> **回滚风险**：回滚到本版本之前的旧包会带回旧的 90 天全局清理（旧代码默认值就是 90）；新版本自身没有全局清理。回滚前先备份并确认能接受。

### 自定义端口

方式一：修改 `ecosystem.config.js` 里的 `env.PORT`，然后重启。

方式二：不修改配置，直接指定：

```bash
# 用 8080 端口启动（仅本次生效）
PORT=8080 pm2 start ecosystem.config.js
```

方式三：想永久固定用某个端口，可以在 `ecosystem.config.js` 的 `env` 中改成：

```js
env: {
  PORT: 8080,
  HTTPS_PORT: 8443,
},
```

### HTTP 与 HTTPS

服务同时监听两个端口，功能完全一致：

- `http://IP:PORT`（默认 3000）：直接可用，无需任何配置
- `https://IP:HTTPS_PORT`（默认 3443）：更推荐。首次访问浏览器会提示「不安全」，点「高级 → 继续访问」一次即可（自签证书，服务器首次启动自动生成）；传输全程加密，且加解密更快

> **为什么 HTTPS 下加解密快得多**：浏览器只在「安全上下文」里开放原生 WebCrypto（硬件加速）。
> `http://localhost` 也算安全上下文，但用手机/其他设备访问 `http://内网IP:端口` 不算，
> 此时页面会自动回退到内置的纯 JS 实现，实测吞吐约 8 MB/s，而原生约 1400 MB/s。
> 回退状态下上传 / 下载会明显变慢，但不会卡住页面；页面顶部会给出 HTTPS 地址提示。

> 可配置项（均可通过环境变量覆盖，默认值见 `ecosystem.config.js`）：
>
> - `PORT`：HTTP 端口，默认 `3000`
> - `HTTPS_PORT`：HTTPS 端口，默认 `3443`
> - `STORAGE_LIMIT_GB`：存储总量上限（GB），默认 `10`。达到上限后上传会被拒绝，并提示清理
> - `LIBRARY_DIR`：目录索引（NeDB）所在目录，默认 `<uploads 父目录>/.library`。**不要放进 uploads**，备份时随 uploads 一起备份
> - `TTL_SWEEP_MS`：批次 TTL 扫描间隔（毫秒），默认 `60000`
> - `UPLOAD_TTL_HOURS`：未完成批次（断点续传的暂存）保留小时数，默认 `48`（2 天）。超时自动回收，下次上传从头再来
> - `TRUST_PROXY`：反向代理部署时设为 `1`（或 Express trust proxy 配置串），`req.ip` 才是真实客户端地址；无痕传输的限流按 IP 记账，不设的话反代后所有用户共享一个桶
> - `STUN_PORT`：无痕传输内置 STUN 的 UDP 端口，默认 `3478`。**局域网直连靠它**（Chrome 的 host 候选是 mDNS 名，跨机器常常解析不了）。设 `0` 关掉，改用自建 `STUN_URLS`
> - `XFER_LIMIT_GB`：无痕传输中转区配额，默认 `8`。**它要比你打算传的单文件大** —— 走中转时才占它，直连不占；太小会在配额处停下（页面会提前警告）

## 反向代理部署

- **子路径挂载可用**：两个页面的 API 全部用相对路径（`api/...`），`https://host/box/` 这种挂载方式下只要代理把前缀透传，功能完整可用。
- **SSE 透传**：无痕传输的事件流是 SSE，反代需关闭缓冲（nginx 加 `proxy_buffering off` 或保持 `X-Accel-Buffering: no` 透传，服务端已发送该响应头）。
- **真实客户端 IP**：反代后请设 `TRUST_PROXY=1` 启动（如 `TRUST_PROXY=1 pm2 start ecosystem.config.js`），
  否则无痕传输的限流按代理 IP 记账，一个用户连错 30 次传输码会把所有用户冻住 10 分钟。

### 为什么必须加认证（上公网前必读）

这个项目**没有任何登录机制**——这是刻意的架构选择（内网工具，零配置），但也意味着只要端口能被访问到，任何人都拥有**全部权限**：

| 接口 | 匿名能做什么 |
|---|---|
| `POST /api/upload/init` + `PUT /api/upload/part` | 把任意文件加密后塞满你的磁盘（直到 10GB 上限） |
| `GET /api/library` / `GET /api/list` | 看到所有批次的时间、密文文件名、大小，以及**目录名与目录结构**（目录名是明文；真实文件名仍在加密清单里） |
| `GET /api/uploads` | 看到未完成上传的文件数、字节数与已收块数（不含真实文件名） |
| `GET /api/download/*` / `/api/archive/*` | 下载任何密文（无密钥解不开，但密文本身会泄露文件量级与元数据） |
| `DELETE /api/folder/*` / `DELETE /api/folders/*` | **无确认直接删除批次或整个目录** —— 服务端已限定只能删本服务创建的日期批次/索引目录，越界与软链接都进不来，但你的文件照样能被清空 |
| `PATCH /api/folders/*` / `PATCH /api/batches/*` | 改目录名、移动目录或批次；没有权限校验 |
| `GET /api/xfer/sessions` | 看到当前有多少无痕传输在进行 |
| `POST /api/xfer/create`（限速后仍可用） | 反复建会话占住活跃会话槽位（默认 20 个），把别人正在用的会话挤掉 |

「在反代层加认证」的意思是：不改这个项目的代码，让 nginx/caddy 在请求到达 file-box 之前先要求输密码。这样所有接口都在认证之后，上表的每一行都打不通。nginx 最小配置（basic auth）：

```nginx
server {
    listen 443 ssl;
    server_name files.example.com;

    # 1) 先要求密码：htpasswd -c /etc/nginx/file-box.htpasswd 用户名
    auth_basic "File Box";
    auth_basic_user_file /etc/nginx/file-box.htpasswd;

    # 2) 把请求转给本机跑着的 file-box
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_buffering off;          # 无痕传输的 SSE 需要关缓冲
        client_max_body_size 64m;     # 分块上传的单块上限（服务端是 32MB，留余量）
    }
}
```

配套两件事：

- **file-box 本身只监听本机回环**，公网只能走 nginx：`PORT=127.0.0.1:3000` 不行（PORT 只支持端口号），用防火墙拦掉 3000/3443 对外，或 pm2 里保持端口不对外开。
- **HTTPS 证书由 nginx 负责**（Let's Encrypt 免费签），此时浏览器是安全上下文，原生 WebCrypto 可用，比直连 IP:3443 的自签证书体验更好——自签证书那套「点高级→继续访问」就不再需要了。

只想在内网用、不想加认证的话：保持现状即可，但请确认 3000/3443 没有被端口转发到公网。

## 存储与删除

- **上传没有单文件大小限制**，但整个服务的存储空间有上限（默认 10GB）
- 页面实时显示「已用 / 上限」用量条；接近或达到上限时变红，并提示删除无用文件，上传按钮自动禁用
- **每次上传的保留期**：默认 1 小时后自动删除，可选 1h / 4h / 8h / 2d / 3d / 5d / 10d / 90d；到期只删这批文件，空文件夹保留
- **文件夹永不自动删除**：只能手动删；删除文件夹会按「批次 → 最深子目录 → 父目录」逐项执行，可在任务中心暂停 / 继续 / 取消
- **没有全局自动清理**：旧备份 / 长期项目资料不会因为目录名日期老而在启动或上传时被删除
- 目录索引在 `<uploads 父目录>/.library`（NeDB 的两个数据文件 + `.bak`），随 `uploads` 一起备份；不要放进 `uploads` 内

### 下载次数

- 每个文件行显示「下载 N 次」；一次都没被取走时写「未下载」而不是留空 —— 空着分不清"没人取过"和"这版没做统计"
- 口径：单文件下载算一次；Range 续传（起点 > 0）不重复计数；旧 `/api/archive` 整包归档让该目录每个文件各 +1。前端拉 `manifest.enc` 不计数 —— 否则这个数字就成了"被点开的次数"。404 与被闸门拒绝的请求不计数
- 账本在 uploads **之外**：默认 `<uploads 的父目录>/.stats/downloads.json`（可用 `DOWNLOADS_FILE` 指定）。放进 uploads 就会被归档打包出去、被下载接口吐出去、被用量算进去
- 重启不丢（内存累加 + 2 秒去抖原子落盘，最坏丢最后 2 秒的增量）；目录被删时它的条目一并清掉
- 服务无认证，任何人可以反复下载刷高数字：它只是展示值，不参与任何权限判断，所以不做防刷、也不记 IP 明细（不把它变成访问日志）

## 使用说明

1. 打开页面是「全部文件」：左侧是目录树，右侧是文件夹列表；点「新建文件夹」建项目组 / 任务目录
2. 点进目录后，点「上传」或把文件拖进主区；上传按钮旁的时长决定这批文件多久后自动删除，默认 1 小时。首页上传落在「未分档」
3. 上传、下载、目录删除都在底部「任务」里显示进度；上传/下载可暂停、继续、取消。刷新页面后，未完成上传会列出来，重选同一批文件即可续传
4. 下载：文件行右侧「下载」；支持 Range 断点续传，暂停后继续会从已有密文处接着下
5. 文件行 / 目录行的「⋯」菜单可以重命名、移动、删除；文件夹删除会逐项执行，可在任务中心暂停/继续/取消。删除不可恢复
6. 搜索框只过滤当前目录；点表头可按名称/大小/上传时间/到期/下载次数排序；勾选多项可批量删除
7. 旧的时间戳上传全部在「未分档」：原链接和下载次数不变；在批次标题上点「移动到…」即可整批整理到正式目录
8. 顶栏「链」复制当前目录直达链接（`?f=<id>`）；旧 `?folder=<批次>` 链接仍能打开。无痕传输是独立入口
9. 每次上传默认 1 小时自动删除（可选到 90 天）；文件夹永不自动删除，也没有全局按天清理

> 项目启动时若没有 `uploads/` 会自动创建；文件以加密形式存储，备份 `uploads/`、`.stats/`、`.library/` 三处即可（`.library` 是目录索引，不要放进 `uploads/`）。
