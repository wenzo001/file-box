# 文件库目录 / TTL / 任务中心

本文只讲文件库（目录、上传、下载、删除、TTL、索引）。无痕传输见 [`transfer.md`](transfer.md)。

## 1 模型：字节与组织方式分开

一次上传仍然是一个**不可变的物理批次**：

```text
uploads/20261027_1431/          ← 批次目录（日期名，路径闸门仍按它认人）
  f_<批次指纹前12位><序号>.enc  ← 密文文件
  manifest.enc                  ← 加密清单（真实文件名只在客户端解密）
```

目录树、批次归属和 TTL 放在 `uploads` 之外的 NeDB 索引：

```text
<uploads 父目录>/.library/
  folders.db      ← 目录：_id / parentId / name / nameKey / parentKey
  batches.db      ← 批次：_id=批次名 / folderId / uploadedAt / expiresAt / ttlHours / manifestHash
  settings.db     ← 公共设置：_id=global / defaultTtlHours
  folders.db.bak
  batches.db.bak
  settings.db.bak
```

- 物理批次永远不因为“改名/移动目录”而移动；目录操作只改索引。
- 没有 `batches.db` 条目的旧批次 = **没有归属目录**：它直接排在最外层「全部文件」里，和根上的目录并排。
- 索引丢失时：文件仍在 `uploads/`，目录树与 TTL 丢失，所有批次回到最外层（没有归属目录）；TTL 丢失只会让文件转为手动删除。
- 一个批次只属于一个目录；批次整体移动支持，单文件跨目录移动不在当前版本。
- 目录汇总 `count / size / downloads / earliestExpiresAt / lastUpdatedAt` 在 `/api/library` 里直接给出；`lastUpdatedAt` 取该目录子树内最近一次上传完成时间（空目录为 `null`），用于目录行直接显示「几个文件 · 最后更新几分钟前」。

## 2 目录规则

- `id`：`f_` + 12 位小写 hex；改名/移动不变，分享链接始终用 `?f=<id>`，**不会跟着名字变**。
- `parentId: null` 表示顶级；层级**不设上限**（Finder 式多级分栏，横向滚动），只保留环检测。
- `name`：NFC 规范化、1–10 个 Unicode 字符；拒绝 `/ \ : * ? " < > |`、控制字符、首尾空白/点、`.`/`..`、Windows 设备名；同一父目录下大小写不敏感去重。改名同样按 10 字校验，界面输入框 `maxlength` 同步卡在第 10 个字并显示计数（服务端仍独立校验，不信界面）。
- 保留名：`全部文件`（那是根的标题，建同名目录会让人分不清）。
- 目录数量上限默认 10000（`MAX_FOLDERS`）；无认证环境下防止无限建目录，超过返回 507。层级无限 ≠ 数量无限。
- **没有「未分档」这个目录**：一个批次要么属于某个目录（`folderId`），要么哪儿都不属于（`folderId: null`）。后者就排在最外层「全部文件」那一栏，和根上的目录并排显示（目录在前、文件在后）；根那栏因此既能上传、也能新建目录、也能把东西拖进去（拖上去 = `parentId: null`）。
- 旧版界面发来的 `__unfiled__` 一律当作「根」（`null`）：`upload/init` 的 `folderId`、`folders` 的 `parentId`、`file-move` 的 `to`、`expectFolder` 都认这个别名，老缓存页不会因此报错。这个 id 不再指向任何目录，`DELETE /api/folders/__unfiled__` 现在是 404。
- 目录名与目录结构对服务器明文可见；真实文件名仍只在加密清单里。


## 3 自动删除时长（全局设置 + 批次快照）

- 白名单：`1, 4, 8, 48, 72, 120, 240, 2160`（1h / 4h / 8h / 2d / 3d / 5d / 10d / 90d）。
- **全局设置**：`settings.db` 里的 `defaultTtlHours` 默认 **1 小时**；界面顶部公共配置区直接改，调用 `PUT /api/settings`。该设置对所有使用者生效，只影响**之后发起**的上传。
- 上传 `init` 不带 `ttlHours` 时，服务端读取当前全局值并写进这一批的 `meta.json`；同一批传到一半时改设置，不会改这一批的时长。`init` 仍接受显式 `ttlHours`，供旧客户端/脚本覆盖（白名单校验）。
- 传完时写 `uploadedAt = finish 时刻`、`expiresAt = uploadedAt + ttlHours`；批次级到期，同一次上传的文件一起消失。
- 文件夹没有 TTL，永不自动删除；批次到期后文件消失，空文件夹保留。
- 没有全局保留期：没有“超过 N 天清理所有目录”的兜底；旧批次没有 `expiresAt`，只能手动删。
- 清理：启动、每 `TTL_SWEEP_MS`（默认 60 秒）、每次上传 init 前扫描 `expiresAt <= now`；**物理删除成功才移除索引条目**，失败保留以便重试。
- 界面：文件/目录行显示「几分钟前 / 几小时后删除」；剩余 **<10 分钟**行标红并写「即将删除」，不弹 toast。上传完成 toast 与上传条都会重复说明「X 后自动删除」。


## 4 文件操作

- 文件身份 = `批次名 + 密文名`；真实文件名只在加密清单里。
- 单文件删除：客户端解密清单 → 删条目 → 重新加密 → 服务端原子替换清单 → 删密文。若只剩清单，整批回收。
- 单文件重命名：只改加密清单里的 `name`，密文名/下载次数不变。
- 并发：清单替换带 `expectedManifestHash`（SHA-256）；已有清单却缺哈希 → 400，旧哈希 → 409，客户端重新拉清单后重试。
- 旧数据没有 `manifest.enc`：允许直接删密文，不能重命名。
- 下载：`GET /api/download/:batch/:file` 支持 `Range`；起点 > 0 的续传不重复计下载次数。客户端用 OPFS 存 partial，完成后再流式解密并按清单明文大小裁剪。

## 5 API

| 方法与路径 | 作用 |
|---|---|
| `GET /api/library` | 目录树 + 批次归属 + TTL + 目录汇总（含 `lastUpdatedAt`）+ 用量 + `downloadsTotal`（历史累计下载）+ `wipeConfirm`（清空确认词，界面不另存一份）+ `memDownloadMaxBytes` / `memZipMaxBytes`（拿不到本地存储时单文件 / 打包的上限，分别由 `MEM_DOWNLOAD_MAX_MB` 与 `MEM_ZIP_MAX_MB` 下发）+ `ttlOptions` + `settings` + `now` |
| `GET /api/settings` | 读取公共设置（`defaultTtlHours`） |
| `PUT /api/settings` | 修改公共设置 `{defaultTtlHours}`；白名单外 400 |
| `POST /api/folders` | 新建目录 `{name,parentId}`；名长 10 字、层级不限 |
| `PATCH /api/folders/:id` | 改名 **或** 移动（一次只改一项）；改名不换 `_id` |
| `DELETE /api/folders/:id` | 递归删除；`?mode=empty` 只删空目录。旧 id `__unfiled__` 已不存在 → 404 |
| `PATCH /api/batches/:batch` | 批次整体移动 `{folderId}` |
| `PATCH /api/batches` | 批量移动 `{names:[],folderId}` |
| `DELETE /api/folder/:batch?expectFolder=<id>` | 删除批次；归属不符 → 409 |
| `POST /api/batches/:batch/file-delete` | 单文件删除 `{file, manifest?, expectedManifestHash?}` |
| `POST /api/batches/:batch/file-rename` | 单文件重命名 `{file, manifest, expectedManifestHash}` |
| `GET /api/uploads` | 未完成上传：uploadId/文件数/块数/字节/最近活动（不含真实文件名） |
| `DELETE /api/uploads/:id` | 取消并清理暂存；合并中置取消标记 |
| `GET /api/list` | 旧接口，保持原形状（只少了 `usage.retentionDays`），供旧缓存/兼容调用 |
| `POST /api/maintenance/wipe` | **一键清空** `{confirm:"清空全部文件"}`：删掉全部批次、暂存与无痕中转，保留目录树 / 全局设置 / 历史累计下载；确认词不对 400 且不动任何文件，清不干净 409（带残留名单） |

请求体由 `lib/schemas.js` 的 Zod schema 校验；错误统一 400；目录/批次不存在 404；同名/非空/状态冲突 409。

## 6 界面与任务中心

浏览界面是 macOS Finder 式**多栏视图**：点一级目录向右展开下一栏，层级不限、横向滚动；每一栏都可以把文件拖进去上传，空白处右键「新建文件夹 / 上传文件到此处」，目录行右键或行尾「⋯」提供打开 / 重命名 / 移动 / 复制链接 / 打包下载 / 删除。顶部搜索是**全局搜索**，同时匹配目录名与解密后的文件名，并显示所在路径。

- 目录行直接显示「N 个文件 · 12.3 MB · 最后更新 X 分钟前」（目录大小 = 该目录下各文件密文之和），文件行标出各自大小（有加密清单时是明文真实大小）；文件行显示上传时间（几分钟前）与到期倒计时，10 分钟内标「热乎」——**热乎只标文件行**，目录行不标（目录的"新"由「最后更新 X 分钟前」表达）。名字与「热乎」同格时只截名字（`.name-text` 省略号），标签 `flex: none` 保持完整、不许被名字挤出格子。文件菜单里的「移动这批上传到…」用于把旧批次整批移入正式目录（批次是物理不可变的，目录只是索引归属）。
- **粘贴上传（电脑端）**：`document` 上的 `paste` 监听（`App.vue` 的 `onPaste`）读 `event.clipboardData.files`（拿不到就退到 `items` 里 `kind === 'file'` 的那几颗），有文件就按当前目录发起一次普通上传（`uploadTargetId`：在最外层就是 `null`，落点也正是最外层）。三条"不许动"：焦点在 `input / textarea / select / [contenteditable]` 里（用户是在往框里贴东西）、弹层开着（`.dialog` 还在 DOM 里）、剪贴板里没有文件（纯文本粘贴原样交回浏览器）。走的是和点「上传」完全同一条分块加密上传路径，所以影子行、进度、续传一并都有。
- **上传中的影子行**：选完文件、任务一开跑，每个文件就在目标目录那一栏里先占一行（`lib/pending.mjs` 把 `tasks` 按 `folderId` 摊开；类别只有 `queued / running / finishing / paused`，完成 / 失败 / 取消即消失）。样式是**虚线框 + 半透明图标 + 第三行一条 3px 进度条**，名字旁写「上传中」（暂停写「已暂停」），第二行是「大小 · N%」；整行 `pointer-events: none` —— 它还不是文件，不许被勾选、拖拽、双击下载。**只给图标降透明度，不用整行 opacity**：整行透明会把文字对比度一起拉下去。栏头把影子单独计数（「0 个文件 · 还没有文件 · 1 个上传中」），不算进"N 个文件"（还没提交）。它不挂 `.file-row` 类（那是"真文件"的选择器），DOM 上仍是这一栏的子元素，所以 `dndRows` 必须按同一顺序把它们算进去（库按"值与子元素一一对应"配对）。传完后影子行消失、`refreshLibrary` 把真实文件行（带「热乎」）填进来。
- 目录「⋯」菜单里的「复制文件夹链接」始终是 `?f=<目录 ID>`；改名不换 ID，所以链接不变。
- 文件分享：文件「⋯」→「复制文件分享链接」，链接带 `file=<批次>/<密文名>`；打开后进入所在目录、目录行高亮、对应文件高亮并列出分享文件清单。多选后在常驻工具行点「复制分享链接」可一次分享多个文件。
- 目录 / 多选打包下载在浏览器内解密后生成 zip（`fflate`，store 不压缩）；服务端只见过密文，所以 zip 只能由客户端拼。**按能力降级**：能写 OPFS 的设备边解密边写盘（压缩包多大都行、每个文件都能断点续传）；没有 OPFS 且总量在 `MEM_ZIP_MAX_MB`（默认 50MB，与单文件下载的上限分开）内时在内存里拼；再大的包**降级成逐个文件下载**（每个文件再走它自己的阶梯），任务行会写明是哪一档。
- 当前目录每 10 秒刷新；切换目录时立即拉一次最新 `/api/library`，并自动横向滚到新展开的那一栏。批次清单哈希在服务端改名 / 删除时会变，轮询看到哈希变化就重拉清单，不会停在旧文件名上。
- 顶部公共配置区：「所有新上传：1 小时后自动删除」；旁注写明到期即永久删除、已上传文件按各自上传时的设置、设置对所有使用者生效。
- **弹层里的回车 = 那颗主键**（`lib/dialog-enter.js` 的 `enterSubmits`，主对话框与清空弹层共用）：新建 / 重命名 / 移动 / 确认删除 / 一键清空都按回车提交。两条不抢：① 中文输入法"上屏"那一发回车（`keydown` 时 `isComposing` 仍为真，部分浏览器只报 `keyCode === 229`）；② 焦点落在别的键上（如 Tab 到「取消」）时让浏览器自己按那颗键 —— 抢了就会"又取消又提交"。配套的一条：弹层打开时把焦点放到"该敲回车的地方"（有输入框放框里，纯确认框放主键上），因为库默认把焦点停在第一个可聚焦元素 =「取消」，不挪的话回车就成了取消。
- 两端是两套壳、同一套业务：桌面保留 Finder 式多栏（`ColumnBrowser.vue` + `RowItem.vue`），窄屏（`≤700px`）换成单层列表 + 返回键（`MobileBrowser.vue`，与桌面共用同一个 `RowItem`）；右键菜单与「⋯」菜单出自同一批构造函数（`folderMenuItems / fileMenuItems / columnMenuItems`），窄屏上换成底部操作表（`ActionSheet.vue`）；任务中心桌面是列表面板、窄屏是底部抽屉（`TaskCenter.vue` 一份实现两个壳）。手机档判据只有一个来源：`composables/useDevice.js` 的 `(max-width: 700px)`，必须与 CSS 的断点同一条。
- 窄屏布局：顶栏**不再钉在屏幕上**（sticky 会把 3～4 行界面层永久压在浏览区头上），品牌与「上传 / 传输 / 设置」共用第一行（目的地改用短标签），搜索独占一行；桌面那条配置条（自动删除时长 + 旁注 + 清理入口）整块收进「设置」底表（`SettingsSheet.vue`，齿轮两端都在，桌面点开是居中弹层），底表里改时长即时生效，清理入口点开即关底表、弹清空确认框。工具行只剩一行状态文字，动作改成**常驻底部动作栏**（全选 / 复制分享链接 / 打包下载 / 删除 / 取消；未选中时后四颗 `disabled`），按钮 44×44，底边按 `env(safe-area-inset-bottom) + var(--kb-inset)` 让位，主区 `padding-bottom` 留出 88px 不压住最后一行。分栏卡片的高度地板写成 `clamp(320px, …, 900px)`（平板档 `clamp(300px, …, 760px)`），一屏装不下就整页滚，任务面板跟在卡片下面——不做"卡片和任务面板抢同一屏"的 flex 布局，实测那种布局在 320×568 会把卡片挤到 62px，栏内行被 `overflow-y: hidden` 永久裁掉。窄屏列表行高 60px、图标 26、名字 15、第二行 12 写大小与「热乎」，行间有分隔线；所有勾选入口的**命中区**撑到 44×44，方框本身桌面 15 / 触摸 20 / 手机 22（44 是"点得到"，不是"画 44"），转发生效靠外面那层 `<label class="check-hit">`，行本身的 `@click` 由这层 `.stop` 挡掉，避免一次触摸勾两次。文本输入一律 16px 起，防 iOS 聚焦时整页放大且回不去。
- 颜色只有一个来源：`web/src/styles/tokens.css`，**只有一套暗色**（不跟随系统主题）。`--brand` 只做装饰（图标/进度条/强调条），要坐文字的地方用 `--accent`；蓝底上的字色是 `--on-accent`、红底上是 `--on-danger`（深色下写死 #fff 分别只有 3.47 / 2.75）。样式分四层：`tokens → base（原子）→ files（列表）→ shell（壳）`。

前端任务状态：`queued → running → paused / failed / done / canceled`。

**一键清空**：电脑端在配置条右端「清空所有文件…」，手机档在「设置」底表里（同一入口，配置条在窄屏不显示）。点开先列出会删什么、保留什么，输入确认词 `清空全部文件` 才放行。服务端删的是：所有「日期_时间」批次目录、未完成上传的暂存、无痕传输的中转密文；**保留**目录树（`folders.db`）、全局自动删除设置（`settings.db`）、历史累计下载数（账本里的 `__total__`，只增不减）；**不动** `.certs/`（删了所有客户端都要重新信任证书），也不动别人放进 `uploads/` 的非批次目录。返回回执里带 `removed`（批次数 / 文件数 / 字节 / 暂存 / 中转）、`kept.downloadTotal` 与 `verified`（三处都空）。**回执丢了不等于没清**：`fetch` 在网络层失败（服务正好重启 / 连接被掐）时，弹层先自己问一次 `/api/library` —— 已经没有文件就按「连接中断，但服务器已确认清空」收掉（只报确认到的事实，不编批次数），还有文件就报「服务器上还有 N 个文件：请重试」，问不到状态就报「没能确认服务器状态：请刷新」。服务端那条路径本来就是幂等的（清空第二次只是 0 个批次）。

| 任务 | 暂停 | 继续 | 取消 | 说明 |
|---|---|---|---|---|
| 上传 | 停发新块，等在途块落定 | 重新 init 拿 `have`，只补缺失块 | 中止在途 + `DELETE /api/uploads/:id` | 刷新后列出服务端未完成批次，重选同一批文件续传 |
| 下载 | abort 当前请求，OPFS 里的密文 partial 保留；重新开始会从断点续 | 从 partial 长度发 `Range` 续（网络断了/15 秒无字节自动重连，退避 1/2/4…最大 30 秒，直到取消） | abort 并清掉密文与明文两份 partial | 密文在 OPFS 里断点续；解密**按块写进第二个 OPFS 文件**再把磁盘文件交给浏览器保存（内存只留一块）。拿不到本地存储的页面只能整份经内存，默认 512MB 封顶（`MEM_DOWNLOAD_MAX_MB`） |
| 目录 / 多选打包 | abort 当前文件请求；已写入的条目保留在磁盘上的压缩包里 | 从头重新打包（密文 partial 还在，不会重新下载，只是重新解密） | abort 并删掉半截压缩包 | 三档：磁盘流式（边解密边写 OPFS）/ 内存（≤ 上限）/ 逐个文件（超上限且无 OPFS） |
| 目录删除 | 当前项完成后停 | 从剩余清单继续 | 停止，剩余保留 | 按“批次 → 最深子目录 → 父目录”逐项；`expectFolder` 防误删被移走的批次 |

- 任务记录目前不做跨刷新持久化（未完成上传通过 `/api/uploads` 恢复；下载 partial 在 OPFS，重新下载同一文件会续）。
- 多标签页不同步任务。

## 7 构建与部署


- 备份：`uploads/`、`.stats/`、`.library/` 三处；`.library` 不要放进 `uploads/`。`.library` 里现在有 `folders.db` / `batches.db` / `settings.db` 及各自的 `.bak`。

- 单实例假设：NeDB 不是多进程安全；`ecosystem.config.js` 只跑一个进程。

## 9 安全边界

- **没有登录**：能访问端口的人拥有全部权限；目录名与目录结构对服务器明文可见，真实文件名与内容仍加密。
- **加密口径要说准**：文件库用的是**部署内置密钥**（`public/crypto.js` 里那把常量经 PBKDF2 派生，随 `dist-web/crypto.js` 一起下发）。明文确实从不上传、服务器磁盘与备份里只有密文，但它**不是**"服务端看不见"的端到端加密 —— 能打开页面的人就取得到密钥，把下载到的密文解开。它防的是"拿到磁盘 / 备份但没拿到程序目录"。**无痕传输那条路才是真端到端**：密钥由一次性码经 ECDH P-256 + HKDF 派生，服务器只有密文帧与摘要，也没有券可回放。
- 上公网前必须在反向代理层加认证；内网使用也要确认端口没有被转发出去。
- 目录名永远不参与文件系统路径；批次名仍走原有路径闸门（日期形状 + realpath 校验）。
- 删除不可恢复（无回收站）；多团队共享盘靠目录约定与二次确认。

## 10 当前版本不做

- 单文件跨目录移动的文件侧、回收站、预览、上传文件夹自动镜像子目录、按目录单独保留期。
- 拖拽移动已交付（目录行走 `PATCH /api/folders/:id`，文件行走 `POST /api/batches/:batch/file-move`），但留一条**未解释的读数**：把客户端那次 `patchFolder` 摘掉之后，「拖拽载体」的 `parentId` 仍然变成了目标目录（台面靠新加的"这次必须真的发出 PATCH"断言才抓住这件事）。
  **2026-10-28 补**：提交点已从 `setValues` 挪到 `drop` 捕获 —— 库在 `pointerover` 到另一栏时就调 `transfer`（= `setValues`），那发生在松手之前；照它提交等于"鼠标没抬起文件就搬走了"（实测：请求 1305ms、drop 1306ms）。现在 `setValues` 一个动作都不做，`drop` 捕获里才发请求，悬停只给 `.drop-here` 高亮。台面改成**真的按住 1 秒**再松：按住期间零请求、目标行有高亮、松手后恰好一次请求。
  能排除的：`App.vue` 里只有两处会改父级（拖拽、移动到…对话框），对话框没开；服务端也没有任何按时间重算父级的路径。
  不能排除的：库在 drop 时把 DOM 挪了位置，而某个我们没想到的地方把它当成了真移动。
  这一格现在由两条判据共同守着（PATCH 调用边 + 父级结果），**别把"结果对了"当成机制清楚了**；下次接手先在这行 PATCH 的 request 监听里打 `req.postData()`，看它是谁发的。
- 手机档的**真机验证仍欠着**：`test/lab/mobile-smoke.js` 跑的是 Chromium 触摸仿真（390 / 360 / 320 三档、`hasTouch` + `isMobile`），能证明命中区、iOS 缩放阈值、裁切、对比度和"触摸点得动"，但证明不了 iPhone Safari 上的两件真事：① 长按拖动（`@formkit/drag-and-drop` 的触摸档要长按才起拖，仿真里没做这条腿）；② `env(safe-area-inset-*)` 在真有刘海和 home 指示条的机器上的实际让位量（仿真里 env() 恒为 0）。这两条要么上真机，要么留在这格，别当成已验。
- **审计那几格现在的状态**（都留了可证伪的读法）：
  - **限速与并发：已修**。`/api/upload/init`、`/api/library` 各有一个按 IP 的固定窗口桶（`INIT_PER_WINDOW` 默认 60、`LIBRARY_PER_WINDOW` 默认 240、`RATE_WINDOW_MS` 默认 60 秒）；`/api/download` 与 `/api/archive` 共用 `MAX_EGRESS`（默认 32）个名额，满了回 429 + `Retry-After`，名额在响应结束/断开时归还。判据：`test/rate-limit.test.js`、`test/egress-limit.test.js`（含"占满后 429、腾出来立刻恢复""别的 JSON 接口不受牵连"；两把刀：路由不挂桶 / 第三个并发不挡）。
  - **仍欠**：没有 `X-Content-Type-Options: nosniff`，也没有 CSP / `frame-ancestors`。上传 `.html` 目前不会执行（下载带 attachment、归档与无痕分段是 octet-stream、SSE 是 text/event-stream），这三条由静态门（扫 `server.js` + `lib/*.js` 的吐字节函数/路由）与行为腿（四条路读真响应头）守着；加安全头属于纵深防御，本版没做。
  - **有意不做**：文件库用一把部署内置密钥（见 §9），混进页面就能解开 —— 要真隔离只能走无痕传输。
- **没有加密清单的旧文件，下载/打包会带 ≤64KiB 的零填充**：上传时明文向上补到 64KiB 的整数倍（"看不出精确大小"那条特性），真实大小只记在加密清单里；没有清单就没有真相。代码里以 `shortcut:` 标注，补清单或迁移旧数据后移除。
- 目录名加密（当前明文；文件内容/真实文件名仍加密）。
- 跨标签页任务同步、任务记录跨刷新持久化（未完成上传和下载 partial 的恢复见 §6）。
- 全局搜索由浏览器拉取并解密所有清单后完成；清单数量极大时首次搜索需要等待「正在读取文件名」，没有服务端明文索引（那会让服务器看见真实文件名，破坏「服务器只见密文」的边界）。
- 目录 / 多选 zip 在浏览器内解密后组装，服务端没有明文，也不能替客户端拼 zip。能写 OPFS 的端是边解密边写盘（不受大小限制），没有 OPFS 且超上限的会降级成逐个文件下载；**暂停后继续是从头重新打包**（顺序流续不了，但密文 partial 复用、不重新下载）。
