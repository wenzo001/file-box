# 2026-10-20

## 无痕传输（transfer.html / xfer-engine.js / lib/transfer.js）针对 2GB 现场的一轮加固

用户现场：2.1GB 文件、标签页在后台很久后任务断掉；发送方不能重发、接收方不能续传；
本地算哈希/切块/加密要等一会儿；两端在同一局域网（HTTPS 入口）却走服务器中转，实测 4.x MB/s；
点"忘记"后无法确认云端密文是否清干净。

定位到的根因（都已修，逐条有测试）：
1. **后台标签被冻结** → 会话期间持一把 Web Locks（`holdAgainstFreeze()`），Chrome 不冻结持锁页面。
2. **retrying/failed 档没有"继续"** → 暂停键文案改成「继续传输」，取消键改「放弃这一单并销毁」；
   `lockForPhase` 里 failed 不再冻结操作排（原来 `dead` 把 failed 也算进去）。
3. **`XFER_LIMIT_GB` 默认 2GB < 2.1GB 文件** → 走中转必定在 2GB 处 413。默认改 8GB；
   `create` 回 `limitBytes/overBudget`；413 文案给"改哪个开关/走直连"。
4. **局域网仍中转**：`STUN_URLS` 空 + Chrome mDNS 候选 → ICE 失败。新增 `lib/stun.js` 内置 STUN
   （udp `STUN_PORT`=3478），按请求 Host 下发 `stun:<host>:<port>`；`server.js` 里 `stunSelf: (host)=>stun.urlFor(host)`。
   超时改成 `switchChannel(..., {keepRtc:true})` + `lateRtcMs`(120s)，直连晚到自动切回 p2p。
5. **4.x MB/s**：`pullMissing()` 原是 `for..of + await`（一帧一个来回）+ 固定 `pollMs=1500`。
   改成 `pullParallel:8` 并发 + 自适应间隔（有进展 40ms，空转 1500ms）。
6. **指纹慢**：`fingerprintFile` 按 `pool.size` 切段并行（≥16MiB 才切，切点对齐 128KiB）；
   worker 的 `fingerprint` op 改为接受 `from/to` 并回 `digests` 数组；顺手修 `P.cat(...chain)` 在 20 万块会 RangeError。
7. **清理不可确认**：新增 `GET /api/xfer/residue?sid=`（**无凭证**，只回 segments/bytes/expiresAt/state），
   单独限速桶 `XFER_PROBE_LIMIT`。页面底部新增「服务器残留核验」栏；「忘记」失败时自动查一次并如实报。

测试：`node --test --test-concurrency=1 "test/*.test.js"` → 122 条（新增 `test/hardening.test.js` 11 条、
`xfer-channel` 3 条：并发拉取 / 晚到直连切回 / Web Lock；`fingerprint` 2 条含分段一致性）。
三条新引擎判据都做了变异验证（pullParallel→1、摘 keepRtc、摘 holdAgainstFreeze 各自只红自己那条）。
`test/helpers.js` 默认 `STUN_PORT=0`（否则每个测试进程抢 udp 3478）。
