## 无痕传输第二轮：P2P 直连成功之后，界面自己没说真话

用户报的三件事（HTTPS 3443 直连已经能用）：① 块进度条一动不动；② 2.5GB 传完，"保存"按钮卡很久才出现；
③ 各种通道/降级模式在界面上长得一样，分不清走了哪条路。

### 根因（都已在代码里定位并修掉）
1. **接收端进度条根本没有样式**：`progress-strip.css` 只写了 `#blocks`，接收端的 `#r-blocks` **一条规则都没有**
   → 没有 flex / 没有格子尺寸 / 没有配色，600 个 `.blk` 全是零尺寸空盒子。那条长条从第一帧起就没画出来过。
   修：选择器改成 `#blocks, #r-blocks` 全量覆盖。
2. **每个进度包整页重画**：引擎每落盘一块就 `emit()`，`paint()` 里重建状态行字符串 + `innerHTML` 重建模式区 +
   逐格比对 600 个格子。千兆下每秒上千次 → 主线程被自己的 UI 占满，进度条在等主线程。
   修：`mount()` 里把 `on(st)` 合并到 `requestAnimationFrame`；状态行/模式区加内容签名，没变不写 DOM。
3. **校验/写盘逐帧串行 + 零进度**：`finishReceive()` 是 `for` 里 `await`（2.5GB 两万帧，一帧一个 worker 来回），
   期间界面只有一句静态文案，保存键压根不在页面上。修：每批 8 帧并发解密（哈希仍按块序）+ `verifyDone/verifyTotal`；
   长条画"第二遍扫描"（`.blk.vfy` 绿色）；保存键提前露出但 disabled（"校验中，还不能保存"）；`saveAll` 同样批量 + `saveDone/saveTotal`。
4. **接收端走中转却显示"正在尝试直连"**：发送端有"没走通道就别说是直连"的规矩，接收端没有（只在 8 秒超时才改标）。
   修：`pullMissing()` 里 `got > 0 && !rtc.open` 就 `switchChannel('server_relay', …, {keepRtc:true})`。
5. **五种模式难区分**：`turn_relay` 与 `server_relay` 共用 'relay' 圆点；"降级"又覆盖同一个点。
   修：圆点只表示通道（绿/蓝/紫/黄），模式区新增 chip 行：通道 · 加密层(ECDH/仅口令) · 引擎(原生/纯JS) · 是否降级，
   每种通道配一句"快不快、为什么、怎么办"。
6. **控制台一条 503 红字**：服务器没配 TURN 时 `upgradeIceWithTurn()` 仍去问 `/turn`。修：记住 `turnConfigured`。

  保存键按相位上锁 / rAF 合并 / 发送端进度取 max。

  `校验中，还不能保存|true` → `保存到这设备|false`、相位轨迹含"正在逐块校验"、零 console.error。
- `test/xfer-channel.test.js` 新增 1 条：校验/写盘必须持续报帧级进度（`verifyTotal = frames - 1`，0 号是清单帧）。

### 已知边界
- 本机 headless Chromium 产不出 ICE 候选 → 冒烟的通道一直是 server_relay；真 P2P 下的同一套 UI 逻辑没在本机复现。
- 全量跑期间出现过一次未复现的 `请求失败 (404)`（先是"卡住了"那条腿，后是"确认重试"那条腿，单独跑都绿）。
  台架里加了 4xx 留痕 `counters.errs`（method+path+status+content-type），下次能直接看出是哪一路。
  **按"未查明"登记，不当已通过**。
